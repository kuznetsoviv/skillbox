# Выбор решения в формате LADR (Lanscape-Alternative-Decision-Rationable)

## Lanscape (контекст)

* Нужно централизованно собирать метрики как с приложений, так и с инфраструктуры.
* Важно получать визуализацию состояния сервисов и окружений.
* Должна быть возможность масштабирования системы мониторинга при росте числа сервисов.

## Alternatives (варианты)

1. **Prometheus + Grafana**
    - Широко используемый стек для метрик.
    - Поддержка формата Prometheus нативно.
    - Большое сообщество, готовые экспортеры.
    - Простота развертывания.
2. **Zabbix**
    - Более старая, но функциональная система мониторинга.
    - Хорошо подходит для серверной инфраструктуры.
    - Для приложений, отдающих метрики в формате Prometheus потребуется адаптация.

## Decision (решение)

Выбираем **Prometheus + Grafana** как основное решение:
- Приложения уже умеют отдавать метрики в нужном формате.
- Простота интеграции и развертывания.
- Легкий старт с возможностью последующего маштабирования.

## Rationable (обоснование)

- Минимальные трудозатраты на интеграцию.
- Популярное решение в отрасли.
- Grafana обеспечивает гибкие дашборды для различных команд.
